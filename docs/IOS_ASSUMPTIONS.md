# iOS 客户端：哪些是观测，哪些是我自己的取值

写这份文件的起因：文档里曾把 iOS 的交互写成「对齐 UU」，但实际上**没有任何 UU 手机端
的包或设备证据**。下面把每个数值按来源摊开，避免再出现把推断当观测的写法。

来源分级：

- **观测**：能在 UU 自己的产物里指到字节或字符串。
- **推断**：从观测的几何/语义推出来，方向可信、具体数值是我的取舍。
- **自研**：UU 那边没有任何依据，纯粹是为了解决具体问题定的工程值。

## 一、观测（来自 UU Windows 客户端 `D:\UU远程\GameViewer\bin\GameViewer.exe`）

| 项 | 证据 | 值 |
| --- | --- | --- |
| 光标素材 | 从 exe 切出 106 个内嵌 PNG，其中 14 个是光标图 | 全部 **64×64** |
| 光标可见部分 | 逐像素解 alpha 求包围盒 | 箭头 42×56（占 tile 高 **88%**），整套平均 **79.5%** |
| 光标热点 | 包围盒原点 | 箭头 **(0,0)**，热区在左上角 |
| 滚轮语义 | 字符串 `view_mode_input result=local_scroll type=wheel axis=`、`sendMouseWheel`、`mouse_wheel result=skipped reason=input_manager_missing` | UU 的 **Windows** 端只有桌面滚轮路径 |
| 缩放档位字段 | `zoom_scale=`、`custom_zoom=`、`view_mode_zoom result=changed percent=` | 存在百分比缩放状态，但没读到具体档位表 |

## 二、推断（有依据，但数值是我定的）

| 项 | 推理 | 我的取值 |
| --- | --- | --- |
| 光标在屏幕上的目标大小 | 桌面指针在 100% DPI 通常 24–32 设备像素；素材箭头占 88% | 目标「箭头≈24 设备像素」→ tile 约 10.1 pt |
| 默认光标 pt | 上一条 + 留一点触摸可见性 | **11 pt**（箭头≈29 px） |
| 光标档位 | 围绕 11 pt 上下各一档 | 9 / 11 / 14 pt（小/标准/大，可调） |

## 三、自研（UU 手机端没有任何依据）

| 项 | 我定的值 | 依据 | 怎么验 |
| --- | --- | --- | --- |
| 两指＝滚轮（不平移） | 永远发滚轮 | 你的直接反馈 | 手测 |
| 放大后如何平移 | 指针顶到可视区边缘才让路 | 为避免和滚轮抢手势 | 手测 |
| 捏合判定阈值 | 跨度变化 ≥4% 才缩放 | 防 2% 抖动误触 | 手测 |
| 滚轮步进 | **12 pt / 格** | 桌面滚轮一格的常见手感 | 手测 |
| 长按 | **0.5 s**、10 px 容差 | 常见移动端长按时长 | 手测 |
| 长按菜单项与文案 | 打开/在资源管理器中显示/重命名/删除/新建文件夹/刷新/属性/清理临时文件 | 抄功能清单（UU 桌面有），文案是我们自己的 | 需 UU iOS 包对比 |
| 传输面板布局 | 汇总行+工具栏+行+限速/覆盖 | 同上 | 需 UU iOS 包对比 |
| 悬浮菜单项顺序 | 照片 / 传输 / 接收的文件 / 文件 | 我们自己的信息架构 | 需 UU iOS 包对比 |

## 四、要把「自研」变成「观测」需要什么

1. **UU 的 iOS 包**（`com.netease.uuremote`，App Store v4.48.1）：插上 iPhone 让我用 usbmuxd 拉，或者把 ipa 丢进 `inbox\`。资源与 `Assets.car` 是明文，能直接量光标尺寸与资源名；`__TEXT` 被 FairPlay 加密，字符串读不到。
2. **UU 的 Android 包**（同一套客户端逻辑，易下载）：dex/native 里的手势常量可读性更好，能直接对齐阈值与步进。
3. 两个都拿不到时，最少也要**录一段 UU 手机端的操作用屏**：两指滑动时画面是否平移、光标多大、长按菜单长什么样，这些都能从录像里量出来。

拿到任意一项后，上表第三段的每一行都能换成实测值，届时再改代码、再出一版 ipa。
